# 前后端解析一致性规范（含 2026-08-19 事故复盘）

> 目的：这条轨道里，「自动化提示词（生成 md 格式）」→「前端 app.js 解析」→「后端 build_cloud.py 解析」是**三套各自独立的实现**。任何一处改格式，其余两处不跟进，就会静默崩坏。本文把规则和一次真实事故钉死，避免重演。

---

## 1. 事故复盘（2026-08-19：理财「今日知识」Tab 内容重复 + 漏 `**`）

### 现象
- 理财「今日知识」Tab 里，`大白话 / 生活化比喻 / 注意什么` 三段内容**互相重叠重复**。
- 段落里冒出字面的 `**申购费**`、`**赎回费**` 等 `**` 符号。

### 直接原因（两个 bug，都在前端 `app.js`）
1. **`bullet()` 的 lookahead 写死了「下一段紧跟 `**`」**：
   ```js
   // 错误写法（会失配）
   var re = new RegExp("\\*\\*[^\\n]*?" + key + "[^\\n]*?\\*\\*：([\\s\\S]*?)(?=\\n\\s*\\*\\*|\\n\\s*##|$)");
   ```
   它假设下一段 marker 是 `\n**...**`。但 md 实际是 `\n🍎 **举个例子**：`——**emoji（🍎/💡）隔在中间**，lookahead 永远命中不了，于是每段都一路吞到文件末尾，`大白话` 把 `比喻 + 注意` 全吃进去、`比喻` 又把 `注意` 吃进去 → **表现为"重复"**。

2. **`bullet()` 返回值没剥 `**`**：
   而 `parseLicai()` 里只有 `tip` 字段手动 `.replace(/\*\*/g, "")`，`dabai / biyu / zhuyi` 三个字段没剥，渲染时又直接 `esc()` 输出 → `**` 字面显示。

### 根因（为什么会出现 / 为什么以前没炸）
| # | 根因 | 说明 |
|---|---|---|
| 1 | **格式规范升级，解析器没同步** | 自动化提示词早就把理财 md 段头定为带 emoji 的 `📌 **一句人话**：` / `🍎 **举个例子**：` / `💡 **对我有什么用**：`（见 `新电脑自动化提示词.md` §理财）。但前端 `bullet()` 的 lookahead 仍按"无 emoji"的旧假设写。 |
| 2 | **前端与后端是两套独立解析器，没对齐** | 后端 `build_cloud.py/parse_lc_md` 的 lookahead **本来就带 emoji 前缀**（`📌/🍎/💡`），是对的；前端 `app.js/parseLicai` 是另一套、错了。而理财「今日知识」Tab 恰恰**走前端那套**，不是后端解析结果 → 后端对、前端错，没被任何人察觉。 |
| 3 | **旧数据"碰巧能跑"，掩盖了 bug** | 早期理财 md 段头格式不统一/无 emoji 时，`\n\s*\*\*` 能命中，`bullet()` 一直"能工作"；直到 LLM 严格按新规范（带 emoji）生成，才暴雷。 |
| 4 | **markdown 标记剥离不集中** | `clean()` 会剥 `**`，但 `bullet()` 返回的字段没走 `clean()`，导致同一份 md 里有的字段剥了 `**`、有的没剥。 |

## 2. 防再犯硬规则（必须遵守）

### R1. 三处实现必须同步
「自动化提示词（md 格式）」↔「`app.js` 解析」↔「`build_cloud.py` 解析」任一处改动，**必须在同一次提交里同步其余两处**，并写进本文件 §3 变更记录。

- 后端 `03_部署脚本/build_cloud.py` 是 `01_站点前端/build_cloud.py` 的**副本**，两者一起改（老规矩，见 MEMORY.md 第 7 条）。

### R2. lookahead 必须容 emoji 前缀
解析"段落边界"时，下一段 marker 行**可能带 emoji**（`📌 🍎 💡 📝 🧠 🔍 ✅ 📊` 等）。正确写法（前端 `bullet()` 已按此修复）：
```js
var re = new RegExp(
  "\\*\\*[^\\n]*?" + key + "[^\\n]*?\\*\\*：([\\s\\S]*?)(?=\\n\\s*(?:[📌🍎💡📝🧠🔍✅📊][^\\n]*?)?\\*\\*|\\n\\s*##|$)"
);
```
后端 `build_cloud.py` 的 `_LC_*_RE` 也要保持 emoji 前缀截断（`📌/🍎/💡/##`）。

### R3. markdown 标记统一出口
**任何"要显示给用户的文本"都必须剥掉 `**`（或走 `clean()`/`inlineMd()`）**，不允许有字段绕过。新增字段时先问：这个字段会不会被 `esc()` 直接输出？会的话必须 strip `**`。

### R4. 改解析器必须做新旧格式回归
改完解析器，**至少用「最新一份 md」+「一份旧格式 md」双跑验证**，确认：
- 每段精确止于边界（不互相吞噬）；
- 无 `**` 残留；
- 无尾部 markdown 分隔符（`---`）残留。
